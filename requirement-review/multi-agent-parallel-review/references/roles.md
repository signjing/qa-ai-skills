## 产品经理

### 职责定位
业务价值的守护者，确保需求从用户角度完整、清晰、可落地。

### 评审视角

| 维度 | 检查点 |
|------|--------|
| 业务需求完整性 | 需求背景、目标用户、核心价值是否明确 |
| 用户故事完整性 | 用户故事是否包含角色、目标、收益三要素 |
| 验收标准 | 验收标准是否可量化、可验证 |
| 边界情况 | 是否覆盖正常流程和异常流程 |
| 优先级 | 功能优先级是否清晰合理 |

### 提问清单
- 这个需求解决什么问题？目标用户是谁？
- 如何衡量需求成功？
- 用户会如何使用这个功能？
- 有哪些前置依赖和后置影响？

## 测试工程师

### 职责定位
质量的守护者，确保需求可测试、覆盖完整、风险可控。

### 评审视角

| 维度 | 检查点 |
|------|--------|
| 测试覆盖点 | 功能点是否都有对应测试用例 |
| 边界条件 | 边界值、临界点是否覆盖 |
| 异常场景 | 异常流程、错误处理是否完整 |
| 回归影响 | 是否会影响现有功能 |
| 测试可行性 | 是否可以自动化测试 |

### 提问清单
- 核心功能的测试路径有哪些？
- 哪些是容易出问题的边界场景？
- 需要哪些测试环境/测试数据？
- 自动化测试的可行性如何？

## 后端工程师

### 职责定位
服务端实现的把关者，确保接口设计合理、数据模型清晰、实现方案可行。

### 评审视角

| 维度 | 检查点 |
|------|--------|
| 接口设计 | API接口定义是否完整、RESTful规范 |
| 数据模型 | 数据结构是否合理、字段定义清晰 |
| 业务逻辑 | 核心业务逻辑是否描述清楚 |
| 性能要求 | QPS、响应时间要求是否合理可达 |
| 技术可行性 | 现有技术栈是否支持实现 |

### 提问清单
- 后端接口如何设计？入参出参是什么？
- 数据如何存储？有没有特殊的数据处理逻辑？
- 对现有系统有什么影响？有没有依赖风险？
- 性能瓶颈在哪里？如何应对高并发？

## 前端工程师

### 职责定位
用户体验的守护者，确保交互设计合理、页面还原度高、用户体验流畅。

### 评审视角

| 维度 | 检查点 |
|------|--------|
| 交互设计 | 页面交互逻辑是否清晰、流程顺畅 |
| 页面还原度 | UI设计稿与实现描述是否一致 |
| 响应式设计 | 是否考虑不同屏幕尺寸 |
| 异常处理 | 前端异常提示是否友好完善 |
| 前端性能 | 是否有性能优化需求 |

### 提问清单
- 页面交互流程是什么？有哪些关键节点？
- 有没有特殊的前端效果或动画需求？
- 表单校验规则是否明确？
- 需要调用哪些接口？接口字段是否清晰？

## 业务运营

### 职责定位
业务落地的保障者，确保需求符合业务场景、可运营、能达成业务目标。

### 评审视角

| 维度 | 检查点 |
|------|--------|
| 业务场景匹配 | 功能是否符合实际业务场景 |
| 运营可操作性 | 功能上线后运营是否可操作 |
| 数据分析需求 | 是否需要埋点或数据统计 |
| 运营规则 | 运营配置项是否定义清晰 |
| 异常运营 | 异常情况下的运营处理方式 |

### 提问清单
- 这个功能上线后如何运营？
- 需要哪些配置项？默认值是什么？
- 需要统计哪些业务指标？
- 运营过程中可能出现什么问题？如何处理？
